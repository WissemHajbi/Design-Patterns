Définition du « Factory »

· Le patron de conception Factory fait partie des patrons de création.
· Il est utilisé pour déléguer la création des objets à des sous-classes ou à des méthodes, ce qui permet de

   découpler le code client (le code d'utilisation des objets) du code de leur implémentation concrète.

· Objectif principal:

      Centraliser et abstraire la création d'objets pour améliorer la flexibilité du code..

· Problématique:

       Ne pas vouloir que le code client connaisse les classes concrètes à instancier.
       Eviter le couplage fort entre le code qui utilise l'objet et le code qui le crée.
       Anticiper des changements ou extensions (ajout de nouvelles classes) sans devoir modifier tout le code..
       Exemple sans Factory:

// Couplage fort : le client doit connaître les classes concrètes

Forme forme = new Cercle();
forme.dessiner();}

· Si demain on remplace Cercle par Triangle, il faut modifier le code partout où Cercle est instancié !!!!

       Solution proposée par Factory

· Déléguer la création des objets à une classe spéciale (la Factory).
· Le client ne connaît pas la classe concrète, il ne dépend que de l'interface ou de l'abstraction.
· Exemple avec Fatcory:

                          // Couplage faible : le client ne connaît pas les classes concrètes

                  Forme forme = FormeFactory.getForme("cercle");
                  forme.dessiner();}

     · Maintenant, si on remplace l'implémentation de "cercle" dans la factory, le client ne change pas !

· Principe:

      · Le client ne crée pas directement les objets via new.
      · Il demande à une "factory" de lui fournir un objet qui respecte une interface ou une classe abstraite.
      · La factory décide quelle classe concrète instancier.

· Avantages :

· Faible couplage : Le client dépend uniquement d'une interface ou classe abstraite, pas des classes concrètes.

· Centralisation de l'instanciation: Toute la logique de création est contenue dans une seule classe (la factory), facilitant la maintenance.

· Respect des principes SOLID (SRP): Le code de création est séparé du code métier.                                                            3

    Les deux variantes de « Factory »

· Le patron de conception Factory présente principalement deux catégories :
     1. Factory Method
     2. Abstract Factory

· Chacune des deux catégories a des besoins spécifiques dans la création d'objets:

1. Fatctory Method

       · Définit une interface pour créer un objet, mais laisse les sous-classes choisir la classe concrète à instancier.
       · Il est utilisé quand une classe ne sait pas à l'avance quel type exact d'objet elle doit créer.

· Abstract Factory

· Permet de créer des familles d'objets liés sans spécifier leurs classes concrètes.

· Il est utilisé lorsqu'on veut s'assurer que des objets compatibles sont créés ensemble.

    Utilisation de « Abstract Factory »

· L'exemple de notification vu avec le patron de conception « Factory Method » peut très bien être étendu pour

   illustrer un usage du patron de conception « Abstract Factory »:

· Il est possible de gérer plusieurs canaux de notification (SMS, Email,..) mais pour chaque canal, on associe

    plusieurs types de messages:
                      alerte,
                      confirmation,
                      rappel,

· Ainsi, pour chaque canal de notification, on créé une famille d'objets pour les types de messages correspondants:

· Exemple:

       · Canal SMS: peut envoyer plusieurs types de messages:

                   · AlerteSMS
                   · ConfirmationSMS
                   · RappelSMS

       · Canal Email: peut envoyer plusieurs types de messages:

                  · AlerteEmail
                  · ConfirmationEmail
                  · RappelEmail

 8 Abstract Factory permet de créer des familles de messages liées à un canal, sans spécifier leurs classes concrètes.
